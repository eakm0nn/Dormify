# DORMIFY — สถานะล่าสุดสำหรับทำงานต่อ

อัปเดต: 13 พฤศจิกายน 2026 (Asia/Bangkok)

เริ่มอ่านไฟล์นี้เมื่อเปิดโปรเจกต์บนอีกเครื่องหรือเริ่มบทสนทนาใหม่
อ่านร่วมกับ [บันทึกการทำงาน](WORK_LOG.md), [กติกา 14 ข้อ](BUSINESS_RULES.md) และ [คู่มือเครื่องใหม่](SETUP_NEW_MACHINE.md)
หากข้อมูลไม่ตรงกับ Working Tree ให้ตรวจโค้ดและ Git status แล้วแก้บันทึกตามหลักฐาน

## จุดที่งานอยู่ตอนนี้

- ปรับคุณภาพโค้ดและความถูกต้องของการจองแล้ว ดู [ผลปรับปรุง](CODE_QUALITY_IMPROVEMENTS.md)
- บันทึกกติกาล่าสุด 14 ข้อแล้ว ข้อ 3, 6 และ 9 ทั้งแนวทางยังรอเจ้าของหอยืนยัน
- ผู้ใช้สั่งให้เก็บบันทึกงานทุกครั้ง จึงเพิ่ม AGENTS.md และเอกสารส่งต่องานชุดนี้
- ยังไม่ได้เริ่มย้าย MySQL หรือพัฒนาระบบผู้เช่า/สัญญา/บิลในรอบส่งต่องานนี้

## เทคโนโลยีและคำสั่งปัจจุบัน

| ส่วน | สถานะ |
|---|---|
| Frontend | React 18 + Vite 5 + TypeScript strict + Tailwind 3 |
| Backend | Node.js + Express 5, JavaScript แบบ CommonJS |
| Database | SQLite + Prisma CLI/Client 5.22.0; ยังใช้ db push ผ่าน db:setup |
| สิทธิ์ | ADMIN / USER; สมัครสาธารณะได้ USER เท่านั้น |
| Environment ตัวอย่าง | client/.env.example และ server/.env.example |
| เริ่มระบบจาก Root | npm run dev หรือ npm start |

Root `dev` เป็น Alias ของ `start`: เปิด Vite และ Backend พร้อมกัน แต่ Backend ใช้ `node` จึงยังไม่ Restart อัตโนมัติเมื่อแก้ไฟล์
หากต้องการ Backend Restart อัตโนมัติ ให้เปิดสอง Terminal ด้วย `npm --prefix server run dev` และ `npm --prefix client run dev`
บน Windows ที่ npm.ps1 ถูก Execution Policy จำกัด ให้แทน `npm` ด้วย `npm.cmd`

## สิ่งที่ทำงานแล้ว

- สมัคร/เข้าสู่ระบบ/ตรวจบัญชีจาก Server/ออกจากระบบพร้อมเพิกถอน Session และตรวจสิทธิ์ API
- หน้า Public อ่าน API จริง ค้นหา/กรองห้อง และดูรายละเอียดห้อง
- Admin บันทึกข้อมูลหอพักครั้งแรก ดู/เพิ่มห้อง ดู/อนุมัติ/ปฏิเสธคำขอ
- User ดูข้อมูลบัญชี คำขอและข้อมูลห้องในคำขอของตนเอง
- ตรวจ ID วันที่ ราคา ความจุ และเลขห้องซ้ำ; Unique roomNumber ต่อ propertyId ในฐานข้อมูล
- ป้องกันอนุมัติหลายคำขอให้ห้องเดียวกันผ่าน API แม้ส่งพร้อมกัน
- Dashboard อ่าน API สรุปจำนวน, ใช้ PrismaClient กลาง, Lazy Loading, Hook โหลดข้อมูลที่ยกเลิกคำขอเก่าได้
- แยก RoomForm/RoomTable, ตั้ง ESLint/Prettier และตรวจตัวแปร/Import ที่ไม่ใช้

## ข้อจำกัดและงานค้าง

- ไม่มี MySQL, ประวัติ Migration เป้าหมาย หรือ Backend TypeScript
- หอพักยังแก้ไขไม่ได้; ห้องยังแก้ไข/ปิดใช้งานไม่ได้; ข้อมูลรูป/สิ่งอำนวยความสะดวกยังไม่ครบ
- PENDING ไม่กันห้อง; หลังอนุมัติห้องเป็นไม่ว่าง แต่ยังไม่มีการกันชั่วคราวหรือหมดอายุตามนโยบายใหม่
- UI Admin ยังไม่มีปุ่มยกเลิก แม้ API รับ CANCELLED แล้ว
- Booking ยังไม่ใช่สัญญาหรือทะเบียนผู้เช่าจริง; ยอดคำขอเป็นค่าเช่ารายเดือน ไม่ใช่ยอดบิลตามสัญญา
- ยังไม่มีระบบผู้เช่า/ผู้พักร่วม/สัญญา/เงินประกัน/มิเตอร์/ใบแจ้งหนี้/การเงิน/แจ้งซ่อม/รายจ่าย/รายงาน/Notifications/Audit จริง
- รีวิวส่งไม่ได้ รายการโปรดอยู่ในสถานะหน้าเว็บ และรายการจองเต็มยังไม่มี Pagination
- แพ็กเกจบางส่วนยังมีช่องโหว่/คำเตือนเดิม งานล่าสุดไม่ได้ทำ Major Upgrade หรือแก้ Dependency ทั้ง Stack
- เอกสาร Phase 0 และตารางวิเคราะห์เก่าเป็นประวัติตามช่วงงาน ไม่ใช่สถานะครบถ้วนปัจจุบัน

## สถานะ Git และการส่งต่อล่าสุด

- ผู้ใช้สั่งให้นำชื่อ/แบรนด์ของโครงการก่อนหน้าออก และเริ่มประวัติ Git ใหม่จาก Snapshot งานปัจจุบัน
- สถานะรอบนี้: ส่ง Snapshot ใหม่ 4450c62 ขึ้น main สำเร็จแล้วด้วย Force-with-lease และปรับ main ในเครื่องให้ตรงกัน
- ตรวจหลังส่ง: main และ origin/main ตรงกัน; ประวัติใหม่เริ่มจาก Snapshot โดยมีผู้เขียน eak เพียงคนเดียว บันทึกผลนี้ส่งตามด้วย Commit เอกสาร
- สำรองประวัติครบด้วย Git bundle ที่ .git-backups/before-contributors-20261113.bundle และ Patch ของงานค้าง; ตรวจ bundle ผ่านแล้ว
- โค้ดและฟีเจอร์เดิมคงอยู่ เปลี่ยนชื่อ Package หลักเป็น dormify และข้อความ Health API เป็น DORMIFY
- คำสั่งล่าสุด: ผู้ใช้ยืนยันให้ลบ LICENSE ระดับ Root หลังได้รับคำอธิบายเงื่อนไขแล้ว; บันทึกการลบตามคำสั่ง ใบอนุญาตฟอนต์และ Dependencies ไม่เปลี่ยน
- หลัง Push ประวัติใหม่ อีกเครื่องที่มีประวัติเก่าควร Clone ลงโฟลเดอร์ใหม่ ไม่ Pull/Merge ประวัติเก่ากลับเข้ามา
- GitHub อาจใช้เวลาประมาณ 24 ชั่วโมงเพื่อปรับ Contributors/สถิติหลังเปลี่ยนประวัติ หากยังแสดงชื่อเก่าให้ตรวจ main และรอ Cache อัปเดต
- สถานะที่เคยระบุว่าเก็บ LICENSE ใน Snapshot เป็นประวัติก่อนคำสั่งลบล่าสุด ให้ยึดคำสั่งและรายการล่าสุดใน WORK_LOG
- รอบลบ LICENSE ใช้ Commit/Push ปกติ ไม่ Rewrite ประวัติ Git เพิ่ม

## จุดเริ่มทำต่อ

1. ตรวจสถานะ Snapshot ใหม่ด้านบน ถ้าเปลี่ยนประวัติแล้วให้ Clone main ใหม่ แล้วติดตั้ง/เตรียมเครื่องตามคู่มือเครื่องใหม่
2. อ่านกติกาและขอบเขตจากผู้ใช้ล่าสุด โดยไม่เปิดนโยบายข้อ 3/6/9 เอง
3. งานพัฒนาถัดไปที่เสนอ: วาง Schema/Migration สำหรับ MySQL แล้วจัดการห้อง → จอง → ผู้เช่า/สัญญา → มิเตอร์/บิล → การเงิน → ระบบประกอบ
4. งานถัดไปยังเป็นแผน ให้เริ่ม Implementation ตามขอบเขตที่ผู้ใช้สั่ง พร้อมอัปเดต WORK_LOG และไฟล์นี้เมื่อจบแต่ละช่วง
