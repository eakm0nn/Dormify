## ลำดับสาธิตให้กรรมการ

ทำบนข้อมูลสาธิตที่แยกบัญชี/ชื่ออ้างอิงชัดเจน ไม่แก้ข้อมูลผู้เช่าจริง ถ้าใช้ชุด API/UI อัตโนมัติจะสร้าง namespace และลบเฉพาะของตนหลังตรวจ

1. หน้าแรกแสดงหอเดียว ห้อง ราคา รูป สิ่งอำนวยความสะดวก และข้อกำหนด
2. สมัคร USER และแสดงว่าไม่มีช่องสมัคร Admin ส่งคำขอเช่าแล้วดูสถานะ
3. Admin อนุมัติ แสดงเวลาหมดอายุกันห้อง เพิ่มทะเบียนผู้เช่าที่ผูก USER สร้างและเริ่มใช้สัญญาที่ลงนาม
4. บันทึกอัตราพร้อมที่มาและเลขมิเตอร์ ออกบิลรอบแรก (ค่าเช่าล่วงหน้า) กับรอบถัดไป (รวมค่าน้ำไฟย้อนหลัง) แสดงว่าบิลซ้ำถูกปฏิเสธ
5. USER เปิดบิลของตน แจ้งโอน/แนบหลักฐาน Admin ตรวจและยืนยัน ผู้ใช้เห็นประวัติ ห้ามแสดงสลิปหรือข้อมูลจริงของคนอื่นต่อกรรมการ
6. แจ้งซ่อม เปลี่ยนสถานะและเปิดแจ้งเตือนเฉพาะผู้รับ เผยแพร่ข่าวสารส่วนกลาง
7. เปิดรายงานรับ–จ่าย เงินประกันแยก และประวัติผู้ทำ/วันเวลา ลองตัวกรองและ CSV
8. บันทึกมิเตอร์วันย้ายออก ตรวจค่าเช่าตามวัน ส่วนลดและยอดปรับน้ำไฟตามหลักฐาน ดูตัวอย่าง ยืนยันปิดสัญญา แล้วบันทึกรับ/คืนเงินจริงและประกันแยก
9. Logout และลองเข้าหน้าที่ต้องยืนยันตัวตน แสดงว่า USER เข้าเมนู Admin ไม่ได้

## ทดสอบก่อนสาธิต

หยุดการใช้งานเว็บจริงชั่วคราว เช็ก Docker/MySQL dormify พร้อม และรัน API/UI ตามลำดับ ห้ามรันพร้อมกัน

```powershell
npm.cmd run check:delivery
npm.cmd --prefix server test
npm.cmd --prefix client run test:ui
npm.cmd --prefix client test
npm.cmd --prefix client run lint
npm.cmd --prefix client run format:check
npm.cmd --prefix client run build
npm.cmd --prefix server run db:check
```

หากรายการใดไม่ผ่าน ให้บันทึกคำสั่ง/สาเหตุจริงก่อนส่ง ห้ามใช้ผลเก่ามายืนยันว่าเพิ่งผ่าน ผลล่าสุดพร้อมประวัติอยู่ใน [ผลทดสอบรวม](TEST_RESULTS.md)

## ชุดไฟล์และข้อมูล

- ส่ง Source, package-lock.json ทั้งสามส่วน, compose.yaml, Prisma schema/migrations, assets ที่เว็บใช้, docs และ PDF ขอบเขต
- ไม่ส่ง .env จริง, node_modules, dist, ผล Browser tests, dump ฐานผู้เช่าหรือภาพหลักฐานผ่าน Git
- ฐาน Docker volume ไม่ตาม Git ไปเครื่องใหม่ หากต้องย้ายข้อมูลเดิมต้องใช้ช่องทางส่วนตัวและสำรอง/ตรวจสิทธิ์แยก ดู [คู่มือติดตั้งและเครื่องมือฐานข้อมูล](SETUP_NEW_MACHINE.md) ไม่ import ทับฐานที่มีข้อมูลโดยไม่ตรวจ
- ไม่มีบัญชี Admin เริ่มต้น สร้างบัญชีบนเครื่องปลายทางด้วยคำสั่งในคู่มือติดตั้งและตั้งรหัสของตน
- check:delivery เป็นการตรวจเบื้องต้น ไม่รับรองทุกชนิด Secret หรือประวัติทุก Commit และไม่ Push ให้อัตโนมัติ

## แบบบันทึกตรวจรับเครื่องปลายทาง

| รายการ | ผู้ตรวจบันทึกผลจริง |
|---|---|
| วันที่/เครื่อง/ระบบปฏิบัติการ | ยังไม่ได้ทดสอบเครื่องอื่น |
| Git commit ที่รับไป | รอ Commit ชุดงานล่าสุด |
| Node/npm/Docker พร้อม | รอตรวจปลายทาง |
| npm ci ทั้งสามส่วนและ setup | รอตรวจปลายทาง |
| db:up/db:setup/db:check | รอตรวจปลายทาง ห้าม Reset/Seed |
| สร้าง Admin และ Login | รอตรวจปลายทาง |
| หน้าแรก/ขอเช่า/บิล/ชำระ/ซ่อม | รอตรวจปลายทาง |
| ผู้ตรวจและข้อแก้ไข | ให้ผู้ตรวจกรอกจริง ไม่ใช้ชื่อหรือผลสมมติ |
