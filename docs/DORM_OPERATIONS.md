# DORMIFY — ระบบบริหารหอพักและผลตรวจ 14 พฤศจิกายน 2026

ใช้ React/TypeScript เดิมและ Express JavaScript + Prisma 5.22 + MySQL Docker ฐาน `dormify` เดียว ไม่ได้ย้าย Stack หรือสร้างฐานแยกตามบทบาท

## กติกาที่ผู้ใช้ยืนยัน

- กันห้องหลัง Admin อนุมัติ เริ่มต้น 72 ชั่วโมง เงินประกันเริ่มต้น 1 เดือน และครบกำหนดชำระ 5 วันหลังออกบิล Admin เปลี่ยนได้ที่ **ข้อมูลหอพัก → นโยบายเช่าสำหรับรายการใหม่**
- ค่ากันห้องเก็บในคำขอ ค่าเช่า/ประกัน/กำหนดชำระเก็บในสัญญา และบิลเก็บราคา/หน่วย/ยอด/ชื่อผู้เช่า/เลขห้อง ณ วันที่ออก เปลี่ยนค่าปัจจุบันไม่แก้รายการเดิม
- ค่าเช่าล่วงหน้า ค่าน้ำไฟย้อนหลังตามมิเตอร์จริง ต้องมีบัญชี `USER` ก่อนเพิ่มทะเบียนและทำสัญญา ผู้พักร่วมไม่มีหน้าที่ชำระแยกจากผู้รับผิดชอบหลัก
- อัตราน้ำไฟไม่มีราคาเริ่มต้น ต้องกรอกอัตราที่เจ้าของตรวจสอบพร้อมที่มาเอง ระบบไม่ได้รับรองความถูกต้องตามกฎหมายของตัวเลขที่กรอก

## วิธีใช้งานตามลำดับ

1. Admin เพิ่มข้อมูลหอพักและห้อง User สมัครสมาชิกก่อนส่งคำขอเช่า
2. Admin อนุมัติคำขอใน **รายการเช่าห้องพัก** ระบบกันห้องและแสดงวันหมดเวลา สามารถยกเลิกการกันห้องได้ก่อนเปลี่ยนเป็นสัญญา
3. ระบบตรวจหมดอายุทุก 60 วินาทีขณะ Backend ทำงาน และตรวจซ้ำเมื่อเปิดข้อมูลห้อง/รายการเช่าหรือทำรายการที่เกี่ยวข้อง หมดอายุแล้วเป็น `EXPIRED` และคืนห้องว่างเฉพาะเมื่อไม่มีสัญญาหรือการกันห้องอื่น
4. Admin เพิ่ม **ผู้เช่า** โดยเลือกบัญชี User แล้วเพิ่ม **สัญญาฉบับร่าง** เลือกผู้รับผิดชอบ ห้อง คำขอที่อนุมัติถ้ามี วันเริ่ม ค่าเช่า เงินประกัน และผู้พักร่วม
5. หลังตกลงและลงนามจริง บันทึกวันลงนามแล้วกด **เริ่มใช้สัญญา** ห้องหนึ่งมีสัญญาใช้งานได้หนึ่งฉบับ คำขอที่ผูกจะเปลี่ยนเป็น `CONVERTED` การกดอนุมัติคำขออย่างเดียวยังไม่ใช่สัญญา
6. Admin บันทึกอัตราน้ำไฟและเลขมิเตอร์ต้น–ปลายรอบที่ **บันทึกมิเตอร์น้ำและไฟฟ้า** วันที่ต้องตรงกับขอบรอบสัญญา เลขสะสมไม่ลดลงและบันทึกตามลำดับวันที่
7. Admin ออกบิลที่ **ใบแจ้งหนี้** รอบที่ 1 เป็นค่าเช่าล่วงหน้าเท่านั้น รอบที่ 2 เป็นต้นไปรวมค่าเช่าล่วงหน้าและน้ำไฟของรอบก่อน ต้องมีมิเตอร์และอัตราครบจึงออกได้
8. User แจ้งโอนเต็มยอดแล้วแนบ PNG/JPEG ไม่เกิน 2 MB; เงินสดให้ Admin บันทึกเมื่อรับเงินจริง รายการยังไม่ถือว่าชำระจนกว่า Admin ตรวจและยืนยัน หากไม่อนุมัติต้องระบุเหตุผล
9. Admin บันทึกรับเงินประกันแยกใน **การชำระเงิน** เมื่อจบสัญญาต้องกด **จบสัญญา** แล้วบันทึกคืนเงินจริง ไม่โอนหรือหักหนี้ให้อัตโนมัติ ประวัติบิลและหนี้ยังอยู่
10. User แจ้งซ่อมจากสัญญาที่ยังใช้งาน Admin เปลี่ยนเป็นกำลังดำเนินการหรือเสร็จแล้วพร้อมผลดำเนินการ ดูรายรับ/รายจ่ายและบันทึกรายจ่ายที่ **รายงานและสถิติ** ข่าวสารส่วนกลางอยู่เมนู **ข่าวสารหอพัก** และ User ดูรายการสำคัญของตนที่ **การแจ้งเตือน**

ตัวอย่างรอบเริ่ม 31 มกราคม: รอบถัดไปเป็น 28/29 กุมภาพันธ์ แล้วกลับมา 31 มีนาคม ไม่เลื่อนวันหลักถาวร บิลแรกไม่คิดน้ำไฟก่อนเข้าอยู่ หน่วยน้ำ 3.5 × 7.125 บาทปัดเป็น 24.94 บาทด้วย Decimal และปัดครึ่งขึ้นสองตำแหน่ง

## ข้อมูลและสิทธิ์

- เพิ่ม 17 Models รวมเป็น 24 Models ของแอป เก็บ Payment/Complaint รุ่นเดิมไว้ ไม่ลบหรือแปลงประวัติเก่าให้ดูเป็นรายการใหม่
- Migration `20261114010000_dorm_operations` เพิ่มตารางและ Booking.holdExpiresAt/holdHoursSnapshot เท่านั้น พร้อมนโยบายเริ่มต้นหนึ่งรุ่นที่ผู้ใช้ยืนยัน ไม่มีผู้ใช้ ห้อง หรือรายการเงินจำลอง
- Migration `20261114020000_invoice_price_precision` ขยายความจุ InvoiceItem.unitPrice เป็น DECIMAL(18,6) ให้บันทึกราคาค่าเช่าได้เท่าช่วงของสัญญา ไม่ลดความละเอียดหรือลบข้อมูล
- Room/Lease/Invoice ใช้ Row lock และ Unique constraints ป้องกันครอบครองห้อง ออกบิล หรือรับชำระซ้ำเมื่อส่งพร้อมกัน
- API หลักอยู่ `/api/operations` แยกสิทธิ์ทุกเส้นทาง Admin จัดการรายการรวม User อ่านเฉพาะสัญญา บิล เงิน หลักฐาน งานซ่อม และการแจ้งเตือนของบัญชีตนเอง
- ภาพหลักฐานเก็บใน PaymentProof เป็นข้อมูลส่วนตัว ไม่อยู่ Public directory ดาวน์โหลดผ่าน API ที่ตรวจเจ้าของ พร้อม attachment/no-store/nosniff ตรวจ MIME, ขนาด และลายเซ็นไฟล์ ไม่ใช่ระบบสแกนมัลแวร์หรือยืนยันความแท้ของสลิป
- รายรับนับเฉพาะ InvoicePayment ที่ Admin ยืนยันและมี InvoiceSettlement วันที่รายรับใช้วันที่ยืนยัน รายจ่ายใช้วันที่จ่ายจริง ประกันแสดงรับ/คืนแยก รายการค้างและสถิติห้องเป็นยอดปัจจุบันทั้งหมด ไม่ได้ถูกตัดตามช่วงวันที่รายรับ
- Audit เริ่มตั้งแต่ใช้งานโค้ดนี้ ไม่สร้างย้อนหลัง เก็บผู้ทำ เวลา กิจกรรม และรายการอ้างอิง ไม่เก็บรหัสผ่าน JWT หรือภาพสลิปใน Log

ชุด API ตรวจสิทธิ์ข้ามผู้เช่า บิลซ้ำ/การยืนยันพร้อมกัน รอบสิ้นเดือนปีอธิกสุรทิน Decimal rounding นโยบาย Snapshot อายุการกันห้อง สลิปส่วนตัว ประกันไม่เป็นรายรับ และราคาค่าเช่าที่เกินหนึ่งล้านบาท

ชุด Chrome ตรวจ Desktop 1440px, Tablet 768px, Mobile 390px ตามหน้าตัวแทน ไม่ใช่การรับรองทุก Browser/ขนาดจอ ทดสอบครั้งแรกใน Sandbox เปิด DevTools ไม่ได้ จึงเปิด Chrome ด้วยสิทธิ์ที่เหมาะสม รอบถัดมาปรับชุดตรวจ Focus ให้ใช้ Tab จริงแล้วผ่าน ไม่มีการข้าม Assertion

ผล TypeScript/Lint/Format/Build และสถานะฐานหลังตรวจปิดงานให้ดู PROJECT_STATUS.md ซึ่งอัปเดตตามคำสั่งรอบสุดท้าย ไม่ใช้ผลเก่าแทนผลที่ยังไม่รัน

## ข้อจำกัดที่ยังมี

- Admin เป็นผู้สั่งออกบิลแต่ละรอบ ยังไม่มีงานอัตโนมัติออกบิล/Email/SMS การตรวจหมดอายุทำงานเมื่อ Backend เปิดอยู่
- มิเตอร์ต้องบันทึกตามลำดับและตรงขอบรอบ ยังไม่มี Workflow เปลี่ยนมิเตอร์หรือแก้เลขที่ผิดย้อนหลัง ถ้าอัตราเปลี่ยนกลางรอบ ระบบหยุดออกบิล ไม่ประมาณหน่วยหรือแบ่งราคาเอง ต้องกำหนดวิธีคิดให้ชัดก่อนต่อยอด
- ยังไม่มีบิลปิดสัญญากลางเดือน การคิดค่าเช่าตามสัดส่วน ใบลดหนี้ หรือแก้บิลที่ออกแล้ว ระบบไม่เดาวิธีจัดการยอดเหล่านี้
- ประกันรับและคืนเต็มยอดครั้งละหนึ่งรายการต่อสัญญา ไม่มีการแบ่งรับ/คืน หักค่าเสียหาย หักหนี้ หรือชำระบางส่วน
- ร่างสัญญาแก้ได้ สัญญาที่ใช้งานแล้วจบได้ แต่ยังไม่มีต่ออายุ/ย้ายห้อง/แก้สัญญาที่ลงนามหรืออัปโหลดไฟล์สัญญา
- ข่าวสารล่าสุด 100 รายการ การแจ้งเตือนล่าสุด 200 และ Audit ล่าสุด 500 ตามตัวกรอง ยังไม่มี Pagination/Export ครบทุกตาราง
- รูปห้องและสิ่งอำนวยความสะดวกแบบอัปโหลด/จัดการเต็มรูปแบบยังไม่เพิ่ม ไม่เติมข้อมูลปลอมแทนข้อมูลจริง
- ยังไม่ตรวจช่องโหว่ Dependency ใหม่ทั้ง Stack และไม่ได้ทดสอบเผยแพร่ Public Internet เน้น Local loopback เดิม
